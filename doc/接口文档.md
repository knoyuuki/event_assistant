# 会务助手 · 外部接口文档（V1.0）

> 适用对象：外部应用 / 智能体（AI Agent）
> 入口地址：`http://<服务器IP>:10025`
> 所有接口路径均以 `/api/ea/` 开头，**必须通过 10025 端口访问**（80 端口拒绝外部接口）。

---

## 1. 接口总览

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/ea/meetings/sort` | POST | **核心接口**：输入人员名单/部门名单 + 部门排序选择，返回排序后名单 |
| `/api/ea/dept-snapshots` | GET | 查询可用部门排序存档（用于"部门排序选择"） |
| `/api/ea/departments` | GET | 查询全部部门名（构造部门名单用） |
| `/api/ea/persons` | GET | 查询人员列表（示例） |
| `/api/ea/echo` | POST | 回显测试（示例） |

## 2. 认证方式：签名校验（必选）

每个请求必须携带 4 个签名头（+ 可选加密头）：

| 请求头 | 必选 | 说明 |
|--------|------|------|
| `X-App-Id` | ✅ | 应用标识（创建密钥时分配，形如 `ea_xxxxxxxxxxxxxxxx`） |
| `X-Timestamp` | ✅ | Unix 秒级时间戳，允许偏差 ±300 秒 |
| `X-Nonce` | ✅ | 每次请求唯一的随机串（同一时间窗内不可重复） |
| `X-Signature` | ✅ | HMAC-SHA256 签名（hex 小写） |
| `X-Encrypt` | ⬜ | `1` = 请求体 AES-256-GCM 加密（推荐） |

### 签名算法

```
string_to_sign = METHOD + "\n" + PATH + "\n" + TIMESTAMP + "\n" + NONCE + "\n" + BODY_SHA256
X-Signature    = hex( HMAC-SHA256( key = app_secret, data = string_to_sign ) )
```

- `PATH`：请求路径（不含域名与 query），如 `/api/ea/meetings/sort`
- `BODY_SHA256`：请求体原始字节的 SHA-256（hex）；无请求体时为 `sha256("")`（`e3b0c442...b855`）
- 开启 `X-Encrypt: 1` 时：**先加密、后签名、后发送**（对密文计算签名）

### 可选加密：AES-256-GCM

- 密钥：`key = SHA-256(app_secret)`（32 字节）
- 随机 nonce 12 字节；输出：`base64( nonce(12B) + tag(16B) + ciphertext )`
- 发送时携带 `X-Encrypt: 1` 与 `Content-Type: application/json`

### 错误码

| 状态码 | 含义 |
|--------|------|
| 401 | 签名缺失/错误、时间戳超窗、nonce 重放、解密失败 |
| 403 | 应用被禁用或密钥过期 |
| 400 | 业务参数错误（如名单为空、名单格式错误） |
| 404 | 路径不存在（外部接口仅 `/api/ea/**`） |

## 3. 核心接口：POST /api/ea/meetings/sort

输入人员名单（部门名单）与部门排序选择，返回排序后的人员名单与部门名单。

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 否 | 会议名称（默认"外部调用"） |
| `input_persons` | string | 二者必填其一 | 人员名单：姓名，支持换行 / 逗号 / 顿号分隔 |
| `input_departments` | string | 二者必填其一 | 部门名单：部门名，支持换行 / 逗号 / 顿号分隔 |
| `sort_snapshot_id` | int | 否 | 部门排序存档 ID（部门排序选择），来自 `/api/ea/dept-snapshots`；缺省用当前部门树顺序 |

> 可只传人员名单（部门名单由匹配到的人员自动推导），也可只传部门名单，或两者都传。
>
> 部门名支持**模糊匹配**：无需填写完整名称，系统会在已知部门中选取相似度最高者，
> 例如「企发部」→「企发部/数智办」、「商客部」→「商客部/上海号百」、「云中台」→「云中台/数集部」。
> 结果按标准部门名去重后参与排序；完全匹配不上的名称保留原样并排在末尾。

### 请求示例

```json
{
  "name": "季度总结会",
  "input_persons": "周伟峰\n唐文琪\n马骁骋",
  "input_departments": "财务部\n办公室\nAIBOC",
  "sort_snapshot_id": 4
}
```

### 响应示例（HTTP 200）

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "app_id": "ea_b640811bebc6f99a",
    "meeting_id": 10,
    "sort_snapshot_id": 4,
    "sorted_departments": ["办公室", "财务部", "AIBOC"],
    "sorted_persons": [
      {"name": "周伟峰", "department": "AIBOC", "position": "三级正", "position_title": "三级正", "position_level": 3.0},
      {"name": "唐文琪", "department": "AIBOC", "position": "三级副", "position_title": "三级副", "position_level": 2.0}
    ]
  }
}
```

### 排序规则

1. 人员：**职位等级** 从高到低（公司领导 > 资深副总裁 > … > 员工）
2. 同等级：按 **部门树顺序**（或所选存档顺序）排序
3. 同部门同等级：按组内顺序（`sort_order`）排序

## 4. 辅助接口

### GET /api/ea/dept-snapshots

查询部门排序存档列表，用于选择 `sort_snapshot_id`。

```json
{
  "code": 0,
  "data": {
    "app_id": "ea_...",
    "items": [
      {"id": 4, "name": "0731半年度会", "note": "半年度会部门排序，by张文祺", "created_at": "2026-07-31 10:00:00"}
    ]
  }
}
```

### GET /api/ea/departments

查询全部部门名（树序），用于构造合法的部门名单。

```json
{"code": 0, "data": {"app_id": "ea_...", "items": ["公司领导", "办公室", "财务部", ...]}}
```

---

## 5. 完整调用流程（智能体）

1. **获取密钥**：向系统管理员申请 `app_id` + `app_secret`（管理员在系统内创建）
2. **查询存档**：`GET /api/ea/dept-snapshots` 获取部门排序存档，选定 `sort_snapshot_id`
3. **构造名单**：可先 `GET /api/ea/departments` 核对部门名
4. **签名调用**：`POST /api/ea/meetings/sort`（可选用 AES-GCM 加密）
5. **解析结果**：`code == 0` 表示成功，取 `data.sorted_persons` / `data.sorted_departments`
6. **异常处理**：401 重试需更换 nonce 与时间戳；403 检查密钥状态；400 检查名单格式

> 完整可运行代码示例见 `examples/api_client.py`（Python）与 `examples/api_client.sh`（Shell）。
