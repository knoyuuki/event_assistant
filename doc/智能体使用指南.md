# 会务助手 · 智能体使用指南（V1.0）

> 本指南面向 AI 智能体 / 外部程序。阅读本文件后，你应当能独立完成：
> 「接收一份人员名单与部门名单 → 调用接口 → 返回排序后的名单」。

---

## 0. 你需要什么

| 信息 | 来源 |
|------|------|
| 服务地址 `BASE_URL` | `http://<服务器IP>:10025`（**仅此端口**，80 端口不可用） |
| `app_id` | 系统管理员分配（形如 `ea_b640811bebc6f99a`） |
| `app_secret` | 创建密钥时一次性展示，请妥善保存 |

如果没有密钥：向管理员申请。密钥由管理员在系统「密钥管理」中创建。

---

## 1. 调用流程（3 步）

### 第 1 步：查部门排序存档（可选，用于"部门排序选择"）

```
GET /api/ea/dept-snapshots
```

响应中的 `items[].id` 即 `sort_snapshot_id`（如 `4` 表示「0731半年度会」存档）。
不传该字段则使用当前部门树默认顺序。

### 第 2 步：构造并签名请求

签名规则（务必逐字照做）：

```
string_to_sign = "POST\n/api/ea/meetings/sort\n<timestamp>\n<nonce>\n<sha256(body_hex)>"
X-Signature = hex(HMAC-SHA256(app_secret, string_to_sign))
```

要点：
- `timestamp`：当前 Unix 秒，服务端校验 ±300 秒（请校准你的时钟）
- `nonce`：每次请求重新生成（≥8 字节随机），**不可复用**
- `body`：JSON 序列化后的请求体字节（UTF-8）；无 body 时 sha256 取空串哈希
- 若启用加密（`X-Encrypt: 1`）：先 AES-256-GCM 加密 body，再对**密文**计算签名

### 第 3 步：发送请求

```
POST {BASE_URL}/api/ea/meetings/sort
Headers:
  X-App-Id: <app_id>
  X-Timestamp: <timestamp>
  X-Nonce: <nonce>
  X-Signature: <signature>
  Content-Type: application/json
Body: {"input_persons": "周伟峰\n唐文琪", "input_departments": "财务部\nAIBOC", "sort_snapshot_id": 4}
```

## 2. 可运行示例（Python）

```python
import hashlib, hmac, json, secrets, time, requests

BASE_URL = "http://<服务器IP>:10025"
APP_ID, APP_SECRET = "ea_...", "你的密钥"

def sign(method, path, ts, nonce, body: bytes) -> str:
    s2s = "\n".join([method, path, str(ts), nonce, hashlib.sha256(body).hexdigest()])
    return hmac.new(APP_SECRET.encode(), s2s.encode(), hashlib.sha256).hexdigest()

def call_sort(input_persons: str = "", input_departments: str = "", snapshot_id: int = None):
    body = json.dumps({
        "name": "智能体排序",
        "input_persons": input_persons,
        "input_departments": input_departments,
        "sort_snapshot_id": snapshot_id,
    }, ensure_ascii=False).encode()
    ts, nonce = int(time.time()), secrets.token_hex(8)
    headers = {
        "X-App-Id": APP_ID, "X-Timestamp": str(ts), "X-Nonce": nonce,
        "X-Signature": sign("POST", "/api/ea/meetings/sort", ts, nonce, body),
        "Content-Type": "application/json",
    }
    r = requests.post(f"{BASE_URL}/api/ea/meetings/sort", data=body, headers=headers, timeout=15)
    return r.json()

# 使用示例
result = call_sort(input_persons="周伟峰\n唐文琪\n马骁骋",
                   input_departments="财务部\n办公室\nAIBOC",
                   snapshot_id=4)
if result.get("code") == 0:
    data = result["data"]
    print("部门排序:", data["sorted_departments"])
    for p in data["sorted_persons"]:
        print(f"{p['name']} | {p['department']} | {p['position']}")
else:
    print("调用失败:", result)
```

## 3. 响应解读

```json
{"code": 0, "message": "ok", "data": {"sorted_persons": [...], "sorted_departments": [...]}}
```

- `code == 0`：成功，`data.sorted_persons`（含姓名/部门/职位/等级）与 `data.sorted_departments`
- `code != 0` 或 HTTP 非 200：见下表处理

| HTTP | 含义 | 处理建议 |
|------|------|----------|
| 401 | 签名/时间戳/nonce/解密问题 | 重新生成 nonce 与时间戳，核对签名算法与密钥 |
| 403 | 应用被禁用/过期 | 联系管理员 |
| 400 | 名单为空或格式错误 | 检查 `input_persons`/`input_departments`（换行/逗号/顿号分隔） |
| 404 | 路径错误 | 确认路径以 `/api/ea/` 开头，且走 10025 端口 |

## 4. 注意事项

1. **时间同步**：服务端只接受 ±300 秒内的时间戳，请保持系统时钟准确
2. **nonce 唯一性**：重复使用同一 nonce 会被判定为重放攻击（401）
3. **名单格式**：人员/部门名单用换行、逗号或顿号分隔均可；人员名未匹配到系统人员时会原样保留在名单尾部（以部门"未匹配"处理）
4. **加密模式**：涉及敏感名单建议开启 `X-Encrypt: 1`（AES-256-GCM，密钥由 app_secret 派生）
5. **调用记录**：每次调用都会记录（调用方 IP、路径、状态码、参数、结果），保留 7 天
